# Security and privacy

Report a problem at the official repository's Issues page using a description and synthetic example only. Do not post passwords, live credentials, real PDFs, identity documents, seals, signatures, SQLite databases, session files or local configuration. GitHub Issues are public. If describing a sensitive vulnerability would expose users, first ask for a private reporting channel without publishing exploit details or personal data.

The application processes files locally and has no telemetry, cloud sync or online identity verification. Password login and role checks constrain operations inside the application. A person who can modify the program or its data files can bypass those controls. Records are not tamper-proof evidence, and the data directory and exported PDFs are not fully encrypted. Use OS access controls and maintain backups according to the actual retention requirements.

An approval is an application workflow state, not proof of legal authorization. Administrators must check real authority. PDF image overlays do not provide reliable electronic-signature certification, trusted timestamps or remote revocation of exported copies. Check the final document and recipient requirements before delivery.

The first public release is 1.0.0. It has no automatic update service or guaranteed support deadline. Review official releases for fixes; any later support commitment must be expressly stated by the publisher.
